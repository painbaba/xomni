# Parallel Research Swarm

## When to use
- "Run 300 agents on <topic>" / "research <market/question> deeply"
- Any research ask where breadth (many angles) or depth (live sources) beats a single prompt
- Recurring data-collection for the user's business decisions (markets, competitors, entry strategy)
- Security-topic research where findings must be web-verified (never assert absence from training data)

## The pipeline (all scripts in C:\Users\HP\ai-workforce\swarm\)
1. `gen_tasks_*.py` — generates tasks.json (dimensions x questions; assert counts match)
2. `swarm_run.py <tasks.json> <results_dir>` — FAST swarm: single-shot LLM per task, model knowledge. ~300 tasks in 3-5 min.
3. `deep_run.py <tasks.json> <results_dir> <cache_module>` — DEEP swarm: each agent searches web, fetches 2-4 pages, synthesizes with citations. ~50 tasks in 3-15 min.
4. `synth_*.py` — merges results into report.md + matrix.csv (synth.py / synth_t3.py / synth_botbypass.py / synth_zt.py / synth_lab.py)
5. `lab/lab.py` (v1 WAF-vs-origin sim, :8899) + `lab/lab2.py` (v2 per-class vuln sinks, :8899) + `lab/lab3.py` (v3 ZERO-TOUCH parser sims, :8898) + `lab/lab4.py` (v4 ANDROID zero-click sims, :8897) + `lab/lab5.py` (v5 iOS zero-click sims, :8896) + `lab_agent.py` / `lab_agent_zt.py` / `lab_agent_android.py` / `lab_agent_ios.py` — local experiment labs (see references/lab-experiments.md + references/zero-touch-lab.md + references/ios-zeroclick-lab.md)

## CRITICAL USER RULE — presence/availability questions (learned the hard way)
NEVER conclude "X does not exist / is not available" from model training data. Training data is stale.
- If the question asks whether a service/player exists in a place (e.g. "is Blinkit in Satna"), agents must answer ONLY from live sources.
- If live pages don't settle it: report "no live evidence found in fetched pages" + confidence low. Absence of evidence ≠ evidence of absence.
- User caught this exact failure (Blinkit HAD entered Satna; agents said no) and was furious. The SYSTEM prompt in deep_run.py now encodes this rule — keep it there.

## Search stack (curl reality on this host — Aug 2026)
- BLOCKED via curl: DuckDuckGo HTML (rate-limits after a few calls), Google News RSS ("Sorry"), Bing HTML, Startpage, SearXNG (antibot captcha)
- WORKS via curl: Bing Web RSS `https://www.bing.com/search?q=<q>&format=rss` (parse <link>), Bing News RSS `&format=rss` on news/search
- Bing RSS IGNORES `site:` and `filetype:` operators — those queries return unrelated junk (verified Aug 2026, unclaimed-amounts PDF hunt). Plain keyword queries only; for file discovery use browser search + direct portal probing.
- MOST RELIABLE: browser-verified search cache (`search_cache.py` — URLs found via real browser, keyed by short phrases). deep_run checks cache FIRST.

- Dedupe URLs; fetch pages with browser UA, strip HTML, cap ~4500 chars/page.

## Pitfalls (all hit in real runs)
- `swarm_run.py`/`deep_run.py` read task file + results dir from argv — pass them explicitly (both were hardcoded once; fixed)
- Results are resumable: existing agent_XXX.json files are skipped — delete the ones you want re-run BEFORE relaunching; glob `agent_0*.json` matches ALL of them (wiped 50 results by accident once)
- `rm -rf` on results dirs triggers smart-approval — fine, but verify the dir was recreated
- Module-level code in lab_agent.py runs on import — guard worker launch with `if __name__ == "__main__":` or importing for tests starts the whole swarm
- CLONING a lab runner for a new lab (sed/python transform): the mission-prompt text embeds the LAB port as a string (e.g. "http://127.0.0.1:8897") — after cloning, grep the new file for the OLD port and sed-replace it, or agents silently probe the WRONG lab (measured: lab_agent_ios.py initially pointed at :8897 Android lab; fixed with `sed -i 's/127.0.0.1:8897/127.0.0.1:8896/g'`). Also update OUT dir + print labels in the same pass.
- Agent code blocks wrapped in `try:` need dedent (textwrap.dedent) or IndentationError burns agent steps
- JSON parsing: models wrap JSON in fences or double-encode — `parse_json` regex-extracts first {...}; `unwrap()` in synth handles nested/double-encoded JSON (findings containing a JSON string)
- Gemini needs `responseMimeType: application/json` for structured output; OpenCode Go needs browser UA + generous timeouts (150-300s for reasoning models)
- 429 handling: adaptive per-channel backoff (min_interval *= 1.8 up to 30s) — 429 is transient, retry; 404/401 = dead key, skip
- "finding": true appears in agent-formatted output as `finding: True` or `PASSED XSS True` — grep patterns must cover both JSON and prose forms
- Search engines block after ~3-6 DDG calls: serialize with 3.5s spacing (search_lock) and prefer Bing RSS + cache
- SHARED CACHE POISONS NEW-TOPIC RUNS (hit Aug 2026, Ardee IPO run — 28/40 results garbage, all conf=low "No live evidence"): `search_cache.py` holds a PREVIOUS campaign's URLs (e.g. Satna quick-commerce). deep_run matches cache keys via `all(kw in ql for kw in key.split())`, so generic words in NEW questions ("split", "hold", "capital", "major", "facility", "cost", "revenue") collide with old keys and feed agents totally unrelated URLs (PDF-splitters, dictionary pages, movie Wikipedia, bank homepages). Agents honestly report "no live evidence" — looks like a clean pass, it's a poisoned cache. FIX for ANY new topic: (a) build a topic-specific `search_cache_<topic>.py`, pass as argv[3] to deep_run (`python deep_run.py tasks.json results_dir search_cache_topic`); (b) seed it ONLY with URLs YOU verified return real topic content (curl each, grep for topic name, confirm meaningful text); (c) order dimension-specific keys BEFORE a catch-all `"<topic proper noun>"` key — deep_run fetches first 3 working URLs so dict order = priority, and the catch-all ensures every question gets seeded URLs since all questions name the topic; (d) pre-flight: assert every task question matches ≥1 cache key before launching — keys are matched by `all(kw in ql for kw in key.split())`, so watch WORD-FORM DRIFT: a question with "inflow" misses a key built on "inflows", "regulatory changes" misses "regulation", "perform" misses "performance" (hit Aug 2026 SBI run — 5/50 questions silently fell through to Bing RSS). One-liner:
  `python -c "import search_cache_<t> as sc, json; t=json.load(open('tasks_<t>.json')); print([x['id'] for x in t['tasks'] if not any(all(kw in x['question'].lower() for kw in k.split()) for k in sc.CACHE)])"`
  → patch keys (add alternate word forms) until it prints none; (e) delete poisoned agent_*.json, re-run. After fix: 50/50 agents in 1.2 min, 43 high/medium confidence.

## Verification before telling the user something landed
- Count result files (`ls results_dir/*.json | wc -l`) and spot-check 2-3 for content quality
- AUDIT MID-RUN, not just at the end: after ~60% of agents finish, scan all results for confidence and "No live evidence" — if most are conf=low/garbage, KILL the run, fix the cache (see cache-poisoning pitfall), delete poisoned files, relaunch. A full 50-agent run only takes ~1-2 min on 6 Gemini keys, so a re-run after fixing search is cheap; a poisoned report is not. Early low-confidence en masse = search problem, not model problem.
- Failed single agent retry: `deep_run.py` is resumable — delete the `agent_0XX.json.fail` marker (and any partial json) for the one task, re-run with same argv; only the missing task executes (`ok=50 fail=0` in ~0.3 min).
- For presence claims: verify yourself via browser search (curl search is blocked — the BROWSER is the reliable search channel on this host)
- Append a "LIVE-VERIFIED FACTS" section to the report marking what was browser-checked vs model-knowledge
- Orchestrator fills page-cap gaps: deep_run caps fetched pages at ~4500 chars — long explainers (finshots-style) get truncated and agents honestly report low-confidence gaps on the cut-off section. If you fetch the FULL article yourself, inject those facts into the report's LIVE-VERIFIED section; the swarm agents can't see past their cap.

## Key technique discoveries (lab-verified, Aug 2026)
- **Encoding-depth WAF bypass**: WAF decodes once (norm=1), origin decodes twice. Fully-encoded payload (EVERY byte %XX uppercase hex, incl. letters and dashes) at depth norm+2 beats the WAF; over-encoding (depth+4) fails (origin can't decode). Partially-encoded payloads leave keywords visible → blocked. This is the systematic rule behind "double-encoding bypasses".
- **HPP**: WAF inspects FIRST p= param, origin uses LAST → clean-first + evil-last bypasses at every normalization level.
- **Presence false-negative lesson applies to LLM agents too**: a deep-swarm agent that finds no live evidence must say "no live evidence found", NOT "not available" — this was the Blinkit-in-Satna bug (user-reported, fixed in SYSTEM prompt).
- **Android zero-click campaign (lab4, 50 agents, ~119 NOVEL-with-evidence lines)**: LF-only SIP line endings bypass CRLF filters (INVITE/REGISTER execute; 6-byte method storage truncates REGISTER→REGIST); MP4 size=0/largesize=0 box family bypasses overflow guards across ALL sample-table boxes + cross-surface type confusion (t=mp3/ogg/wav/webm route to MP4 parser); SMS UDL=0 with trailing data (parser ignores TP-UDL overflow) + SMS-NDEF polyglot (same bytes valid for two zero-click parsers); RCS file: URI canonicalization (single-slash/backslash/tab-trim) + schema confusion (file.url bypasses rcs-uri filter); ADTS sample-rate-index 15 (0xF) bypass with executed=true; QUIC high 2-byte varint frame types trigger overflow blocker via derived value (varint decode confusion). Full report: C:\Users\HP\ai-workforce\swarm\report_android_zeroclick.md
- **iOS zero-click campaign (lab5, 50 agents, ~132 NOVEL-with-evidence lines, 13.3 min)**: CoreMedia stsd child box size=0/0xFFFFFFFF reach sample-descriptor parser (nested boxes unvalidated) + co64 64-bit chunk-offset overflow + negative offsets (stco 0x80000000) = OOB CMBlockBuffer semantics + stbl cross-box contamination (trun/tfhd/sidx under stbl) + nested moov recursion; WebKit NUL/NBSP/soft-hyphen in scheme (java\x00script:) + data:text/javascript allowed while data:HTML blocked + HTML entity-encoded schemes (&#106;avascript:) + NOVEL SMIL <animate attributeName="href" values="..."> injection family (entity/tab/CR/NL/NUL variants); plist XInclude (xi:include href="file:///etc/passwd") bypasses the plist-xxe DTD filter entirely (works in string/key/array contexts, data: URIs, SSRF to same host) — the standout finding; PassKit webServiceURL/barcode.message have NO scheme allowlist (javascript:/file:/content://intent:/android-app: all accepted) + CRLF in authToken + formatVersion=-1 accepted + truncated JSON executes + __proto__ traversal; IOKit 0xff-saturated length/count fields reach usb-len-overflow; AudioToolbox ALAC magic + any 4 bytes executes with zero structure validation + CAF 64-bit chunk sizes up to 0xFFFFFFFFFFFFFFFF accepted (heap-overflow primitive); AWDL all-zero payloads enter parser.
