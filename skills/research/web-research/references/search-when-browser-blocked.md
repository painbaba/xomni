# Search & article access when the browser is down or sites block curl

Verified on this host (Aug 2026, git-bash + native Windows curl.exe, browser daemon unreachable).

## Search-engine fallback ladder (curl-only)
1. **Bing News RSS — works via curl, gives direct publisher URLs.**
   ```
   curl -s -A "<browser UA>" "https://www.bing.com/news/search?q=<query>&format=rss" \
     | grep -oE '<title>[^<]*</title>|<link>[^<]*</link>' | sed 's/<[^>]*>//g' | paste - -
   ```
   `<link>` values are `bing.com/news/apiclick.aspx?...&url=<publisher-url>` redirects — the real article URL is the percent-encoded `url=` param. Queries accept OR / quoted phrases, but over-specific multi-word phrases return "no results" — loosen to 2-4 key terms.
2. **Google News RSS — works via curl for discovery:**
   `https://news.google.com/rss/search?q=<query>&hl=en-US&gl=US&ceid=US:en`
   Gives headlines, but its `<link>` values are JS interstitial redirects — `curl -L` lands on a "Google News" placeholder page, NOT the article. Never treat a Google-News-RSS hit as fetched; it is headline-only evidence.
2b. **Guardian open API — keyless article discovery by date range.** `https://content.guardianapis.com/search?q=<terms>&from-date=YYYY-MM-DD&to-date=YYYY-MM-DD&page-size=20&api-key=test` returns JSON with exact `webUrl`s. The literal string `test` works as an api-key for low-volume queries. Excellent for finding a story's exact URL when search engines are blocked and you know roughly when it ran. Then fetch the article HTML directly (guardian.com allows curl with a browser UA).
2c. **AP News search endpoint is server-rendered — works via curl.** `https://apnews.com/search?q=<terms>` (plus `&p=2`, `&p=3` for pagination) returns full HTML; article URLs are greppable as `https://apnews.com/article/<slug>-<32-hex>`. AP's search ranks by relevance and misses older stories — vary the query terms (e.g. add "flight logs", "released") and page through. Beware: the on-page result-count ("123,577 Results") is inflated; and a headline seen in Google News RSS may not surface in AP's own search at all.
3. **r.jina.ai reader proxy** — `https://r.jina.ai/<full-url>` returns clean markdown for most publishers (worked for wionews.com; theguardian.com reachable). CAVEAT: anonymous access to `news.google.com` is blocked (403 AbuseAlleviationError, message says "blocked until <timestamp>") — it cannot resolve Google News redirects. Use it on publisher URLs directly.
4. **Dead ends via curl (bot-walled — don't retry, go to 1/2):** DuckDuckGo html (rate-limits after 2-4 queries), Mojeek, searx.be (antibot captcha), Bing web-search HTML (JS-rendered, zero results in raw HTML). NOTE (corrected Aug 2026): **DuckDuckGo Lite is NOT a dead end** — `lite.duckduckgo.com/lite/?q=<query>` with a browser UA returns real results. It rate-limits to HTTP 202 after ~2-3 rapid queries but RECOVERS after 5-10s sleep. Extraction: results are `<a rel="nofollow" href="//duckduckgo.com/l/?uddg=<urlencoded-url>&...">`; decode with `urllib.parse.unquote(html.unescape(uddg_value))` — BOTH steps (unescape alone leaves `%3A`-style encoding). Use it as the first general web-search fallback when no web_search tool is registered. Also: Bing search in the BROWSER works for a few queries, then a Cloudflare "Verify you are human" checkbox → "Verify" button that hangs — don't fight it, switch to Bing News RSS.
1b. **Bing News VERTICAL in the browser** (`bing.com/news/search?q=<query>`) — when the regular Bing web SERP returns only generic/geopersonalized results (this host, Aug 2026) and Bing News RSS misses, the browser-rendered News vertical returns real, dated news items with outlet + date in the result list. Extract result URLs via console: `Array.from(document.querySelectorAll('a')).filter(a => /<topic>/i.test(a.textContent) && a.href.includes('http'))`. Exact-phrase queries (`"flight log" "1998" "2005"`) return "No results found" pages — loosen to 2-4 key terms. IMPORTANT: a "No results found" page for a person+document pairing (e.g. `Wexner Epstein "flight log"` → 0 results) is legitimate evidence-of-absence — report it as a finding ("not verifiable in any coverage found"), don't keep re-hunting.

## Resolving a Google News redirect when you must
- Use a JS-capable browser on the interstitial URL, or
- find the same story's direct publisher URL via Bing News RSS (most stories are indexed there), or
- reconstruct the publisher slug and fetch via r.jina.ai (Guardian slugs are date-based; a guessed slug 404s — search before guessing).
- **Do NOT try to decode the `news.google.com/rss/articles/<token>` token (verified dead end, Aug 2026).** The token is base64url of a protobuf whose only real field is a string (`AU_yqL...`) that is ITSELF base64url of an opaque/obfuscated blob — no plaintext URL anywhere. Generic protobuf string-dumping, inner base64 decode, and a Googlebot UA all fail (the interstitial is a JS shell, not a server 302). Budget zero tool calls here; go straight to 2b/2c or outlet search instead.

## Article text extraction (messy news HTML)
- Article HTML strips to ONE giant line; line-length filters and naive truncation miss the quotes you need. Use phrase-anchored context windows: `scripts/extract_article_context.py file.html "term1|term2|phrase three"` (prints ±N chars around each keyword hit, deduped).
- Save curl output under explicit `$HOME`/`/c/Users/<user>/...` paths, NEVER `/tmp`: native Windows curl.exe misparses `/tmp/` and writes where bash's `/tmp` isn't — signature: curl prints HTTP 200, then `wc -c /tmp/x.html` says "No such file or directory". (Same class as the MSYS-path traps in devops/windows-gitbash-terminal.)

## Verification / output discipline for live research dossiers
- Classify every source three ways in the final "LIVE-VERIFIED FACTS" section: (a) **fetched OK** — HTTP 200, text extracted, quote verified; (b) **headline-only** — seen in an RSS index but the article could not be opened (say so); (c) **blocked** — name the blocker. Never merge (b)/(c) into (a).
- Keep exact numbers verbatim, each with its URL. Separate the document's content from media interpretation (e.g. an outlet headline saying "emails refute X" is framing; quote the email itself when possible).
- If a claim (e.g. "Robert Maxwell was a spy") cannot be verified in mainstream coverage after several query phrasings, REPORT the absence explicitly — it is a finding, not a failure. Don't assert it from training memory either way.
- Multi-release stories: identify the distinct releases (court-unsealing vs DOJ tranche vs congressional mandate) before quoting counts; different releases have different page/name totals (e.g. Epstein files: 943-page Jan-2024 SDNY batch per Reuters/USA Today — some outlets say 946, quote per-source; ~100-page Feb-2025 "Phase I" with a contact list of 349 names of which 221 were new vs the 2015 Gawker black book, which held 249 names; ≥8,000 files / ~11,000 links in the Dec-2025 EFTA release; then DOJ batches from Dec 2025 and 3M+ files on Jan 30, 2026, heavily redacted to protect survivors).

## Verifying official document releases (downloaded PDFs)
When the primary source is a government press release with linked documents (DOJ, court dockets, agencies): download the actual files and verify first-hand instead of trusting outlet page-count claims.
- The release page's document links are greppable from the article HTML (`document.querySelectorAll('article a')` in the browser, or grep for `media/<id>/dl` — justice.gov pattern: `https://www.justice.gov/ag/media/<id>/dl?inline`). Download each with curl.
- Count pages with pypdf: `len(PdfReader(path).pages)`. Regex-counting `/Type /Page` FAILS on modern compressed PDFs (object streams) — returns 0/partial; pypdf is reliable.
- Extract page-1 text with `PdfReader(path).pages[0].extract_text()` to verify provenance stamps — e.g. the DOJ flight log PDF is stamped "*Publicly released in U.S. v. Maxwell / GOVERNMENT EXHIBIT 662-RR / S2 20 Cr. 330 (AJN)*", which is first-hand proof the document was already public as a criminal-trial exhibit (answers "new vs old" without relying on media framing).
- Cross-check: the release text itself often states the framing (DOJ Feb-2025 release: "largely contains documents that have been previously leaked but never released in a formal capacity") and internal counts ("approximately 200 pages" received vs "thousands of pages" withheld) — quote the release verbatim, then reconcile with your own page counts (my pypdf count of the four linked PDFs: 223 pp total = flight log 118, contact book 95, masseuse list 7, evidence list 3).
- **Age-gated gov document libraries (cookie pass-through, verified Aug 2026):** justice.gov/epstein blocks curl with an Akamai interstitial for HTML, and direct PDF URLs 302-redirect to `/age-verify?destination=...` (an "Are you 18?" gate). Fix: open the PDF URL in the browser, click "Yes" — this sets cookie `justiceGovAgeVerified=true` (visible via `document.cookie` in the console). Then re-fetch with curl adding `-H "Cookie: justiceGovAgeVerified=true"` and the PDF downloads directly. General pattern: browser click-through → harvest the gate cookie → reuse it in curl for bulk downloads. (Files live under `justice.gov/epstein/files/...` — the "Prior DOJ Disclosures" accordion on `/epstein/doj-disclosures` consolidates the Feb-2025 Phase-I batch.)
- **Guessed-URL trap (verified Aug 2026):** a guessed article slug that returns HTTP 200 is NOT evidence you found the right article — NBC returned a completely unrelated story (synovial sarcoma) for a guessed `rcna` ID. After any guessed-URL fetch, verify the page topic matches the slug/title before quoting. Prefer resolving slugs via Bing News RSS/Vertical, CDX, or Wikipedia refs.
