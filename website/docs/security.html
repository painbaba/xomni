Security

XOMNI runs with the same privileges you give it — no more. This page describes the threat model and the controls in place.

Threat model

  • Prompt injection. Untrusted content (web pages, files, emails) can try to steer the agent. XOMNI treats tool output as data, not instructions.
  • Secret exfiltration. Keys and tokens must never reach prompts, logs, or sponsor lines.
  • Supply chain. The free-model pool and plugins must be verifiable and re-verifiable.
  • Local compromise. A malicious plugin or model output must not silently escalate privileges.

Sandboxing

The sandbox-gate plugin sits between the agent and your system. Risky actions — writes outside the workspace, shell commands with side effects, network calls to unknown hosts — are gated behind a policy:

  • Actions outside the workspace require explicit approval.
  • Policies are per-project and stored in config, never in prompts.
  • The gate logs every decision locally for later review.

Secrets handling

  • API keys are referenced as env:VAR or stored in the OS keychain — never in plaintext config files.
  • Secrets are redacted from logs, transcripts, and statusline output.
  • The omni-memory plugin scrubs credential-shaped strings before persisting anything.

Model pool trust

The 25 free models are verified against opencode.ai/zen/go/v1 before use and re-verified on a schedule; a model that fails verification is dropped from the pool. Requests carry only the data you route — sponsor lines, telemetry, and prompts are never mixed into the model request path unless you opt in.

Sponsor-line isolation

Sponsor messages are rendered locally by perkline and are treated as untrusted display strings. They can't touch the model pool, your files, or your keys. Sponsorship is off by default.

Updates

Pull updates with git pull --ff-only; config, keys, and memory live outside the checkout and are never overwritten by updates. Security fixes are announced in the repository release notes.

Responsible disclosure

Found a vulnerability? Please report it privately before disclosing publicly — open a security advisory on github.com/painbaba/xomni rather than a public issue. Include the affected version, a minimal repro, and the impact. We'll acknowledge within 48 hours and aim for a fix in the next release.
