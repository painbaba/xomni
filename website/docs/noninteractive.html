    Non-Interactive Mode

    XOMNI is non-interactive everywhere: every mutating command — CLI and plugin — accepts --yes, failures are loud and name their cause, and there are zero silent cancels. Piping printf 'Y\nY\n' into a command is never needed.

    The policy

    • Every mutating command accepts --yes / -y. The flag is stripped before paths and URLs are parsed, so it is never misread as an argument. Commands that already never prompt accept it as a no-prompt guarantee.
    • Failures are loud. CLI commands exit non-zero and print the cause; plugin commands return a FAILED — <cause> line that names the problem. No bare return or except: pass swallows an install error.
    • Zero silent cancels. Nothing prints "Cancelled" and walks away. The only no-op outcomes are explicit: already registered — nothing to do, skipped N already present, or the plan-then-confirm flow that prints the exact re-run command.

    Verification

    The .bench/test_fail_loud.py suite invokes every audited command with --yes and asserts the action is performed (via stubbed handlers), then simulates each failure mode and asserts the cause is named — in both the CLI and the plugin-command surfaces. It also greps the audited files to prove the --yes flag exists and that no input( prompt call remains. See docs/NONINTERACTIVE.md for the full policy.
