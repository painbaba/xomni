# XOMNI Website

Static marketing/skills site for **XOMNI** — a sellable AI-agent product.
The site is plain HTML/CSS/JS with **no build step**: everything is
generated by small Python scripts and can be hosted on any static host.

## Layout

```
website/
├── index.html            # landing page (built separately)
├── skills.html           # XOMNI SKILLS catalog page (generated)
├── css/style.css         # site-wide styles (optional, if present)
├── js/                   # shared scripts (if present)
├── data/
│   └── skills.json       # machine-readable skills catalog (generated)
├── docs/                 # documentation pages (built separately)
└── scripts/
    └── gen_skills.py     # regenerates skills.html + data/skills.json
```

The skills data source of truth is the repository's `skills/` directory:
**170 `SKILL.md` files** (as of this writing) across **42 domain folders
** (e.g. `skills/creative/ascii-art`, `skills/mlops/inference/llama-cpp`).
Each `SKILL.md` carries YAML frontmatter (`name`, `description`); the
category is derived from the top-level folder path.

## Regenerate the skills page

Whenever skills are added, removed, renamed, or their descriptions change:

```bash
cd website
python scripts/gen_skills.py
```

What it does:

1. Recursively scans `<repo>/skills` for every `SKILL.md`.
2. Parses YAML frontmatter (`name`, `description`; falls back to the
   folder name for `name`).
3. Derives `category` from the path (first path segment).
4. Writes `data/skills.json` (array of `{name, category, description, dir}`).
5. Writes `skills.html` — a self-contained dark-themed catalog page with a
   vanilla-JS search box + domain filter dropdown. The data is embedded
   inline in the page (plus available at `data/skills.json`), so it works
   on any static host with no API calls.

Requires Python 3.9+ with PyYAML (`pip install pyyaml` if missing).

Sanity-check the output:

```bash
python -c "import json;print(len(json.load(open('data/skills.json'))))"
# → 170
```

## Preview locally

```bash
cd website
python -m http.server 8000
```

Then open <http://localhost:8000/skills.html> (and
<http://localhost:8000/index.html>). Quick smoke test:

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8000/skills.html   # 200
curl -s http://localhost:8000/data/skills.json | python -c "import sys,json;print(len(json.load(sys.stdin)))"  # 170
```

## Deploy

### GitHub Pages (recommended)

The repo is `painbaba/xomni`.

1. Push everything (including `website/`) to the `main` branch:

   ```bash
   git add website
   git commit -m "website: add XOMNI skills catalog"
   git push origin main
   ```

2. On GitHub: **repo → Settings → Pages → Build and deployment →
   Source: "Deploy from a branch"** → Branch `main`, folder `/website` →
   **Save**. (The same works with `gh-pages` branch + `/ (root)` if you
   prefer a separate branch.)

3. The site is live at
   `https://painbaba.github.io/xomni/skills.html` within a minute or two.
   Note the site lives under the `/xomni` repo path, so links are relative.

### Cloudflare Pages

- **Dashboard:** Cloudflare dashboard → **Workers & Pages → Create →
  Pages → Connect to Git** → select `painbaba/xomni` → Build command
  *(leave empty — static site)* → Build output directory: `website` →
  **Save and Deploy**. Set the production branch to `main`.

- **Wrangler CLI:**

  ```bash
  cd website
  npx wrangler pages deploy . --project-name xomni
  # or:  wrangler pages deploy . --project-name xomni
  ```

  (First run prompts you to create the `xomni` Pages project.)

### Any static host (Netlify / Vercel / S3 / nginx)

Publish the contents of `website/` as the site root. Build command:
none. Publish directory: `website`.

## Updating the site after skill changes

```bash
cd website
python scripts/gen_skills.py     # regenerate catalog
python -m http.server 8000       # preview
git add skills.html data/skills.json
git commit -m "skills: regenerate catalog (N skills)"
git push origin main             # GH Pages redeploys automatically
```
